# StarVNT Vendor Booking Dashboard

Production-minded assessment project for StarVNT: a responsive vendor booking dashboard with authentication, vendor profile management, event inquiry management, analytics, and deployment-ready structure.

## Stack

- Frontend: React + TypeScript + Vite, React Query, Recharts, Lucide icons
- Backend: Node.js + Express + TypeScript
- Database: MongoDB (used in this repo for direct access)
- Auth: JWT bearer tokens with bcrypt password hashing
- Deployment shape: frontend on Vercel, backend on Render

I chose a split React/Node architecture so the Vercel frontend and Render API can deploy independently while still being easy to run locally.

## StarVNT Product Fit

The dashboard is modeled around StarVNT's current positioning: cinematic weddings, corporate MICE, concerts, Moniqui luxury gifting, FTAura styling, premium venues, and Aura+ AI-assisted event planning. The UI follows the live website's dark cinematic palette, gold CTAs, serif brand accents, and luxury event language.

## Local Setup

```bash
npm install
cp backend/.env.example backend/.env
# set DATABASE_URL in backend/.env to your MongoDB connection string
npm run seed --workspace backend
npm run dev
```

Frontend: `http://localhost:5173`
Backend: `http://localhost:4000`

## API Overview

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/me`
- `GET /api/vendor/profile`
- `PUT /api/vendor/profile`
- `GET /api/inquiries`
- `POST /api/inquiries`
- `PATCH /api/inquiries/:id/status`
- `GET /api/analytics`

## Database Design

- `User`: authenticated vendor account with role support
- `VendorProfile`: marketplace-ready partner profile, category, coverage, pricing, specialties, rating
- `Inquiry`: client event inquiry with event type, budget, date, status, priority, source

This keeps vendor identity, public profile data, and booking pipeline data separated so the model can grow into admin review, multi-user vendor teams, payments, proposal documents, and availability calendars.

## Environment

Backend:

```txt
DATABASE_URL="mongodb://localhost:27017/starvnt"
JWT_SECRET="replace-with-a-long-random-secret"
PORT=4000
CLIENT_ORIGIN="http://localhost:5173"
```

Frontend:

```txt
VITE_API_URL="http://localhost:4000"
```

For production, set `CLIENT_ORIGIN` to your Vercel frontend URL. If you need multiple allowed origins, separate them with commas:

```txt
CLIENT_ORIGIN="https://starvnt-frontend.vercel.app,https://www.your-domain.com"
```

## Vercel Frontend

The frontend is already ready for Vercel. In the Vercel project settings, set:

```txt
VITE_API_URL="https://starvnt-1.onrender.com"
```

Then redeploy the frontend so Vite bakes the Render API URL into the production bundle.

## Render Backend

This repo includes `render.yaml` for Render Blueprint deployment.

- Root Directory: `backend`
- Build Command: `npm ci && npm run build`
- Start Command: `npm run start`
- Health Check Path: `/health`

Set these Render environment variables:

```txt
DATABASE_URL="mongodb+srv://..."
CLIENT_ORIGIN="https://starvnt-frontend.vercel.app"
JWT_SECRET="generated by Render blueprint, or set your own strong secret"
NODE_ENV="production"
NODE_VERSION="22"
```

Render provides `PORT` automatically, so you do not need to set it manually.

## Docker Backend (optional)

If you prefer Docker (existing `backend/Dockerfile`), build/run as follows from repo root:

```bash
docker build -f backend/Dockerfile -t starvnt-vendor-api .
docker run -p 4000:4000 \
  -e DATABASE_URL="mongodb://host.docker.internal:27017/starvnt" \
  -e JWT_SECRET="replace-with-production-secret" \
  -e CLIENT_ORIGIN="https://your-frontend-domain" \
  starvnt-vendor-api
```

For production, set `DATABASE_URL` to a managed MongoDB connection (Atlas) and configure secrets in your host provider.

## CI/CD

Deploy the frontend to Vercel and the backend to Render. CI should install dependencies and build both workspaces before release.

## Production Considerations

- Use a managed MongoDB database such as MongoDB Atlas.
- Store JWT secrets and database URLs only in Render/Vercel environment variables.
- Keep `CLIENT_ORIGIN` locked to the deployed Vercel domain.
- Add refresh tokens or short session rotation for higher security.
- Add role-gated admin endpoints for StarVNT operations teams.
- Add audit logs for inquiry status changes.
